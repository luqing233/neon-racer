# NEON RACER · 霓虹赛车

一个从零实现的**网页版俯视角街机赛车游戏**：程序化生成的霓虹赛道、带漂移与氮气加速的街机物理、会真正抢线的 AI 对手、完整比赛规则（计时/圈数/名次/记录）以及键盘与触屏双操作。
零运行时依赖、零图片素材（所有画面与音效都是代码生成的），使用 **Canvas 2D + TypeScript + Vite**。

```bash
cd neon-racer
npm install       # 仅安装开发依赖：vite / typescript / vitest
npm run dev       # 开发模式，浏览器打开 http://127.0.0.1:5173
```

生产构建与本地开玩：

```bash
npm run build     # 类型检查 + 打包到 dist/
npm start         # 零依赖静态服务器，浏览器打开 http://127.0.0.1:4173
```

## 1. 操作方式

| 操作 | 按键 |
| --- | --- |
| 油门 / 刹车·倒车 | `↑` `W` / `↓` `S` |
| 转向 | `←` `→` 或 `A` `D` |
| 手刹（漂移） | `空格` |
| 切换视角（跟随 / 俯视） | `V` |
| 暂停 | `Esc` / `P` |
| 重新开始 | `R` |
| 车辆脱困（回到赛道） | `C` |
| 切换音效 | `M` |
| 调试信息 | `F1` / `H` |

触屏设备会自动显示屏幕按键（左侧转向、右侧油门/刹车/手刹）。

**漂移 → 氮气**：高速（>170 单位/秒）时按住 `空格` 并打方向，车尾会甩出并进入漂移（约 0.25 秒入漂，漂移角可达 24°，松手即恢复抓地）；持续侧滑约 1.5 秒充满充能条，随即自动释放一段强力加速。这是刷圈速的核心技巧——现在的漂移是可控的，不会轻易打转。

## 2. 玩法与内容

- **两种视角，随时切换**（按 `V` 或菜单里选）：
  - **第三人称跟随 CHASE CAM（默认）**——主流街机赛车的跟随方式：镜头绕着「车身行进方向（速度方向，而非车头朝向）前方的一点」旋转，所以漂移时能看到车身横过来；转向时机头带阻尼跟随、漂移时加快甩动，速度越快镜头拉得越远越高，撞击时镜头后坐。低机位通过远景视差（背景相对赛道的位移）表现，画面因而有俯角纵深感。
  - **俯视 NORTH-UP**——经典北上俯视图，赛道全局一目了然，适合研究走线和刷圈速。
- **程序化赛道**：任意种子（seed）生成闭合环道，包含连续曲率变化的弯道、可变路宽、路肩、护栏、起跑线与真实走线的 AI 行车线；同一 seed 永远生成同一条赛道。赛道现已加长加宽（实测 150 seeds/风格的包络：环道 13.5k–16.9k、技术 10.9k–14.5k、高速 17.5k–19.4k 长，路宽 176–264 单位），弯道最小半径从 190 提高到 300，给操作留出充足余量。
- **三种赛道风格**：`circuit` 均衡环道 / `technical` 低速技术赛道 / `speedway` 高速环，另有随机风格。
- **三种车型**：均衡 / 漂移 / 疾速，各自有独立的动力、抓地、转向与氮气参数。
- **四档 AI 难度**：新手 / 标准 / 高手 / 疯子，AI 会在弯前刹车、走行车线、超车、被卡住时倒车脱困，也会犯错。
- **完整比赛规则**：发车倒计时、逐圈计时、最快圈、名次实时计算、冲线判定、冲线后成绩结算。
- **记录系统**：按「赛道种子 + 风格」在 `localStorage` 保存最快圈与最快总时间，菜单中显示当前选中赛道的记录。
- **音效**：WebAudio 实时合成的引擎声（随转速变化）、轮胎打滑、草地颠簸、碰撞以及倒计时/圈数/最快圈提示音，无音频文件。

## 3. 技术栈与架构

| 关注点 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | TypeScript（`strict`） | 多模块并行开发需要可执行的接口契约 |
| 渲染 | Canvas 2D（手写渲染器） | 俯视角街机赛车不需要 3D 引擎，2D 画布可做到 60fps 且零依赖、零素材 |
| 构建 | Vite 8 | 秒级热更新，产出静态文件可直接部署到任意静态托管 |
| 测试 | Vitest（node 环境） | 纯逻辑模块可在无浏览器环境下做属性测试与完整比赛仿真 |
| 验证 | 零依赖 CDP 驱动 + 真实 Chrome 截图 | 端到端跑真实浏览器，产出可复核的截图与数值证据 |
| 运行时依赖 | 无 | 全部画面与音效由代码生成 |

    vehicle.ts         街机车辆物理：轮胎抓地、漂移、氮气、撞墙、路面（owner: engine-dev）

  ui/
    input.ts           键盘 + 触屏输入（owner: ui-dev）

### 设计要点

1. **先冻结契约，再并行开发**：`types.ts` / `config.ts` / `math.ts` 由 lead 先写完并冻结，四条工作流（模拟、表现、界面、验证）各自只写自己的文件，互不冲突。
2. **固定步长模拟**：物理以 1/120 s 子步推进（`PHYSICS.subStep`），渲染与模拟解耦，30fps 与 144fps 下行为一致；相同种子 + 相同输入 ⇒ 相同结果。
3. **确定性 PRNG**：赛道生成与 AI 抖动都使用 mulberry32，便于测试与复现（含 `?seed=` 之外的调试接口 `window.__NEON__`）。
4. **可测量的验收**：`window.__NEON__` 暴露 `startRace / tick / press / state / standings`，验证脚本可以在无头 Chrome 中确定性地推进比赛、采样状态并截图。

## 4. 测试与验证

```bash
npm run typecheck   # tsc --noEmit，全仓库严格类型检查
npm test            # Vitest：单元测试（tests/unit）+ 独立验证测试（tests/verify）
npm run shoot       # 无头 Chrome 端到端驱动 + 截图，产出 artifacts/report.json
```

- `tests/unit/**`：赛道生成确定性、物理不变量（不穿墙、不发散、限速）、整场比赛仿真。
- `tests/verify/**`：不信任实现自测的独立属性测试（确定性、NaN 排查、名次与圈速规则、玩家可驾驶性）。
- `tests/lead/**`：集成层验收探针（9 条 seed×风格赛道能否被简单纯追踪控制器跑完整圈）。
- `tools/**`：零依赖 CDP 客户端、静态服务器、截图流水线、对抗性检查脚本、v2 功能验证与开局卡顿探针。
- `VERIFICATION.md`：独立验证者的原始证据、逐项 PASS/FAIL、性能数据与最终结论（v1 报告 + `ADDENDUM v2` 追加验证）。
- `artifacts/`：27 张真实浏览器截图（菜单 / 倒计时 / 比赛中 / 漂移 / 加速 / 双视角 / 手机竖屏 / 暂停 / 反向警告 / 45° 旋转检查等）与 `report.json`、`adversarial.json`、`v2-report.json` 机器可读报告。

## 7. 已知限制

- 需要现代浏览器（Chrome / Edge / Firefox / Safari 均支持 Canvas 2D 与 ES2022）；`file://` 直接打开 `dist/index.html` 会被浏览器的模块 CORS 规则拦截，请用 `npm start` 或任意静态服务器。
- 音频需要一次用户交互（浏览器自动播放策略），首次点击后才会出声。
- 触屏操作在小屏手机上可玩，但 UI 主要为桌面/横屏优化。
- AI 在极紧的弯道里才会拉手刹漂移，多数漂移时长短于充满一次氮气所需（1.5 s），因此 AI 很少吃到氮气加速——直道极速和弯道节奏才是它的强项，漂移→氮气这套连招留给玩家。
- 护栏碰撞刻意做得宽容（贴墙滑行时有轻微的顺墙对齐辅助），正面撞击依然会明显减速；“卡在墙角”可以按 `C` 复位或倒车脱困。
- 少数随机种子在生成赛道时会重试，最坏约 230 ms（典型 20–60 ms）。开发环境无头模式用的是软件光栅化（SwiftShader），帧率与 rAF 间隔不代表真实 GPU 表现；真机 60 fps 由主线程约 11 ms/帧和 2.9–3.2 ms 的 `draw()` 保障。
- 真实 GPU 帧率、音频听感、物理多点触控与非 Chromium 浏览器未经实测（验证环境只有无头 Chrome，且没有声卡）。
